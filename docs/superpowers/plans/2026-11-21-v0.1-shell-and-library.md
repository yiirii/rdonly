# v0.1 Shell + Library Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Windows installer and an iPhone Home-Screen app (same code) where you can import EPUB/PDF/CBZ files, see them in a cover grid, and trust that they stay put.

**Architecture:** One Vite + React app. Two storage interfaces chosen at runtime: `RecordStore` (book metadata records) and `FileStore` (book files). Electron implements both on disk through a preload bridge; the browser implements records in IndexedDB and files in OPFS (IndexedDB fallback). Import = read bytes → hash → detect format → extract metadata + cover → write file, then record. No reader and no sync yet — records already carry `updatedAt`/`deleted` so v0.3 sync slots in.

**Tech Stack:** Electron, electron-builder, Vite, React 18, TypeScript, Zustand, Framer Motion, fflate (zip), pdfjs-dist, idb, Vitest + fake-indexeddb + happy-dom, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-21-reader-design.md` (§4 storage, §5.1 identity, §5.2 `books` fields, §6 library, §8 look, §10 workflow).

## Global Constraints

- Flat colours only — **no gradients anywhere** (CI test greps built CSS for `gradient(`).
- Animate **transform/opacity only**; honour `prefers-reduced-motion`.
- Dark theme default. Keycap buttons with solid lip; cards with 1px light top edge.
- Book id = SHA-256 hex of file bytes.
- Cover thumbnail: WebP, ≤ 40 KB, max 300 px wide.
- Every record: `id`, `updatedAt` (ms epoch), optional `deleted: true`.
- Electron: `contextIsolation: true`, `nodeIntegration: false`; renderer reaches disk only via preload IPC.
- Playwright projects: `iphone` 390×844 (touch, mobile UA) and `laptop` 1440×900.
- Never weaken an animation for performance without asking Justin.

## Review Focus

1. **Same file imported twice, or renamed** → one book, status `duplicate`; never two cards. (Task 6 test)
2. **A bad file in a batch** (`.mobi`, truncated zip, 0-byte) → that file reports `unsupported`/`error`, the rest import. (Task 6 test)
3. **EPUB/CBZ with no title or no cover** → title from filename (extension and `_`/`.` cleaned), flat placeholder cover. (Tasks 4, 7 tests)
4. **Storage write fails (quota/full)** → no half-imported book: file write first, record second, file removed if record write fails; user sees a message. (Task 6 test)
5. **App relaunch** → library identical after reload in both shells (persisted, not just in memory). (Task 9 e2e)

### Task 6: Import pipeline

**Files:**
- Create: `src/library/types.ts`, `src/library/importBooks.ts`, `tests/unit/import.test.ts`

**Interfaces:**
- Consumes: Tasks 2–5.
- Produces:
  ```ts
  interface BookRecord extends BaseRecord {
    title: string; author?: string; series?: string; volume?: number
    format: BookFormat; tag: BookTag; modeOverride?: string
    coverThumb?: string // data URL of thumb
    fileName: string; fileSize: number; addedAt: number
  }
  type ImportStatus = 'added' | 'relinked' | 'duplicate' | 'unsupported' | 'error'
  interface ImportResult { fileName: string; status: ImportStatus; bookId?: string; message?: string }
  function importFiles(files: { name: string; bytes: Uint8Array }[], deps: { records: RecordStore; files: FileStore; now?: () => number }): Promise<ImportResult[]>
  ```
  Rules: hash exists + file present → `duplicate`; live record + file missing → write file, `relinked`; tombstoned record → write file, clear `deleted`, `added`; new → write file then record; record write throws → `files.remove(id)` and `error`. Title = meta.title ?? `titleFromFileName`. Files processed sequentially; one failure never aborts the batch.
