# v0.5 Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Library, progress, collections and synced settings follow Justin between laptop and iPhone through his Firebase project, offline-first, never losing a record.

**Architecture:** The app keeps writing to its local `RecordStore` exactly as today. A wrapper (`syncedRecords`) records every local write in a persisted outbox. A `SyncEngine` pulls remote changes (newest `updatedAt` wins, deterministic tie-break), pushes the outbox (a remote write only lands if it is newer than what is there), and listens live. The engine talks to the cloud through a small `Remote` interface: `firebaseRemote` in the app, `memoryRemote` in tests.

**Tech Stack:** Firebase JS SDK v12 (modular; `firebase/auth`, `firebase/firestore`), lazy-loaded. Vitest, Playwright, Firebase emulators in CI only (Google hosts are blocked from the dev sandbox).

**Spec:** docs/superpowers/specs/2026-11-21-reader-design.md §5, §5.4, §12

## Global Constraints
- Email + password only. No Google/OAuth popups.
- Firestore path `users/{uid}/{collection}/{id}`; rules restrict `users/{uid}/**` to that uid (already published by Justin).
- Records carry `updatedAt` and optional `deleted: true` tombstone; newest `updatedAt` wins; first sync merges record by record.
- Synced collections: `books`, `progress`, `collections`, `collectionItems`, `settings`. Local-only settings (`LOCAL_ONLY_SETTINGS`) never leave the device (they're in localStorage, not records, so they can't).
- Book files never upload. A book whose file is not on this device shows "Not on this device — tap to add the file".
- Spark free tier: no polling; one live listener per collection; progress writes already throttled to 15 s.
- Firebase config is public (`src/sync/config.ts`).
- Flat colours, transform/opacity-only motion, reduced motion honoured.

## Review Focus
1. Clock skew between devices: a phone with a clock 5 min behind must still receive and send changes (cursor uses server time, not `updatedAt`).
2. Two devices edit the same record with the same `updatedAt` → both end with the same value.
3. Offline for days with many edits, app closed and reopened → everything pushes once online; nothing pushed twice needlessly.
4. Signing out mid-push / signing into a different account → no data written under the wrong uid.
5. A remote tombstone for a book whose file is on this device → book disappears here too (file removed), as with a local delete.

### Task 1: Merge rules + outbox wrapper (pure, unit-tested)
`src/sync/merge.ts`: `wins(incoming, local): boolean` (newer `updatedAt`; tie → larger stable JSON wins). `src/sync/outbox.ts`: `syncedRecords(local, outbox)` returns a `RecordStore` that writes locally and appends `col/id` to an outbox kept in a local collection `_outbox` (never synced). `applyRemote(local, col, rec)` writes without touching the outbox and returns whether it changed anything.
Tests: newer wins, older loses, tie converges both ways, tombstone newer wins, applyRemote never enqueues, outbox dedupes `col/id`.

### Task 2: SyncEngine with memoryRemote (unit-tested)
`src/sync/remote.ts`: `interface Remote { pushIfNewer(uid, col, rec): Promise<boolean>; pullSince(uid, col, cursor): Promise<{ recs; cursor }>; watch(uid, col, cursor, on): Unsubscribe }`; cursor = opaque server-ordered value. `memoryRemote()` for tests (server counter as time).
`src/sync/engine.ts`: `createSyncEngine({ local, remote, uid, cursors, onChange })` with `start()`, `stop()`, `syncNow()`, `status` (`{ state: 'off'|'syncing'|'idle'|'offline'|'error', pending, lastSyncAt, error? }`). First sync: pull all, then push outbox; on first sign-in for this device all local records are enqueued.
Tests (two "devices" sharing one memoryRemote): converge after edits on both; delete on A removes on B; same-ms edits converge; offline A's outbox survives restart then flushes; clock-skewed device still exchanges; push never overwrites a newer remote record; stop() mid-push writes nothing after stop; cursor resumes without re-pulling everything.

### Task 3: Firebase remote + auth (lazy) and emulator CI
`src/sync/config.ts`, `src/sync/firebaseRemote.ts` (Firestore docs carry `_at: serverTimestamp()` for the cursor; `pushIfNewer` in a transaction), `src/sync/auth.ts` (`signUp`, `signIn`, `signOut`, `resetPassword`, `onUser`), all via dynamic `import('firebase/...')`.
`tests/emulator/firebaseRemote.test.ts` runs the Task 2 two-device suite against the real SDK + emulators; `.github/workflows/sync-emulator.yml` runs `firebase emulators:exec --only auth,firestore`; `firebase.json` + `firestore.rules` mirror the published rules (and the rules test: another uid is denied).

### Task 4: Wire into the app
`src/state/sync.ts` zustand store: user, status; starts the engine on sign-in, stops on sign-out; local writes go through `syncedRecords`; remote changes reload library/settings (debounced 300 ms); a remote tombstone for a book also removes its local file. `#debug` hook can swap in a memoryRemote + fake auth for e2e.

### Task 5: Account & Sync UI + ghost cards
SettingsSheet "Account & Sync": signed out → email, password, Sign in / Create account, Forgot password; signed in → email, status line ("Up to date · 2 min ago" / "Offline · 3 changes waiting" / error in plain words), Sync now, Sign out (keeps everything on this device). Library: books without a local file show a dimmed cover with a cloud mark and "Not on this device"; tapping opens the file picker and the matching file relinks.
E2E (fake remote shared between two browser contexts via exposeBinding): sign in on both → import on A appears as ghost on B → progress on B shows on A → delete on A disappears on B; offline queue; errors (wrong password) in plain words.

### Task 6: Release v0.5.0
Full suite, perf unchanged, CHANGELOG, review subagent, one fix pass, merge, installer link. Justin checks real sign-in on both devices.
